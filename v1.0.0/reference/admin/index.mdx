The Admin API provides comprehensive administrative capabilities for managing the Weir AI platform, including user management, system monitoring, and organizational oversight.

## Overview

The Admin API is designed for system administrators and platform managers who need elevated privileges to manage users, organizations, and system-wide operations. These endpoints require administrative authentication and provide access to sensitive system data and operations.

## Authentication

All Admin API endpoints require Bearer Token authentication with administrative privileges:

<CodeBlock lang="bash">
Authorization: Bearer <admin_jwt_token>
</CodeBlock>

## Available Endpoints

### Authentication & Security

<CardGroup cols={2}>
  <Card title="Admin Login" icon="sign-in">
    `POST /auth/login` - Authenticate admin user and receive access token
  </Card>
  <Card title="Admin Logout" icon="sign-out">
    `POST /auth/logout` - Logout and invalidate admin session
  </Card>
  <Card title="Refresh Token" icon="refresh">
    `POST /auth/refresh/token` - Refresh expired access token
  </Card>
</CardGroup>

## Rate Limiting

Admin API endpoints have higher rate limits than standard API endpoints:

- **Standard Admin Operations**: 1000 requests per hour
- **Log Retrieval**: 100 requests per hour
- **Bulk Operations**: 50 requests per hour
- **System Monitoring**: 200 requests per hour

## Error Handling

All Admin API endpoints return consistent error responses:

<CodeBlock lang="json">
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "Human-readable error message",
    "details": {
      "field": "field_name",
      "reason": "Detailed error reason"
    }
  },
  "timestamp": "2024-01-15T10:30:00Z"
}
</CodeBlock>

## Common Error Codes

<AccordionGroup>
  <Accordion title="Authentication Errors" icon="exclamation-triangle">
    - `UNAUTHORIZED`: Invalid or expired token
    - `INVALID_CREDENTIALS`: Invalid username or password
    - `TOKEN_EXPIRED`: Access token has expired
    - `INSUFFICIENT_PRIVILEGES`: User lacks required permissions
  </Accordion>
  
  <Accordion title="Validation Errors" icon="exclamation">
    - `VALIDATION_ERROR`: Request data validation failed
    - `REQUIRED_FIELD`: Missing required field
    - `INVALID_FORMAT`: Invalid data format
    - `CONSTRAINT_VIOLATION`: Data constraint violation
  </Accordion>
  
  <Accordion title="Resource Errors" icon="search">
    - `NOT_FOUND`: Resource not found
    - `ALREADY_EXISTS`: Resource already exists
    - `CONFLICT`: Resource conflict
    - `GONE`: Resource no longer available
  </Accordion>
  
  <Accordion title="System Errors" icon="server">
    - `INTERNAL_ERROR`: Internal server error
    - `SERVICE_UNAVAILABLE`: Service temporarily unavailable
    - `RATE_LIMITED`: Rate limit exceeded
    - `MAINTENANCE_MODE`: System in maintenance mode
  </Accordion>
</AccordionGroup>

## Best Practices

<AccordionGroup>
  <Accordion title="Security" icon="shield">
    - Always use HTTPS for all API calls
    - Store admin credentials securely
    - Implement proper token rotation
    - Monitor admin access patterns
    - Use least privilege principle
  </Accordion>
  
  <Accordion title="Performance" icon="tachometer">
    - Implement proper caching strategies
    - Use pagination for large datasets
    - Batch operations when possible
    - Monitor API response times
    - Implement retry logic with exponential backoff
  </Accordion>
  
  <Accordion title="Monitoring" icon="chart">
    - Log all admin operations
    - Monitor API usage patterns
    - Set up alerts for critical operations
    - Track error rates and response times
    - Implement audit trails
  </Accordion>
  
  <Accordion title="Error Handling" icon="exclamation-triangle">
    - Implement comprehensive error handling
    - Provide meaningful error messages
    - Log errors for debugging
    - Implement graceful degradation
    - Use appropriate HTTP status codes
  </Accordion>
</AccordionGroup>

## Getting Started

1. **Obtain Admin Credentials**: Contact your system administrator for admin API credentials

3. **Explore Endpoints**: Start with basic operations like getting organizations
4. **Implement Error Handling**: Add proper error handling for all API calls
5. **Monitor Usage**: Set up monitoring and logging for your admin operations
