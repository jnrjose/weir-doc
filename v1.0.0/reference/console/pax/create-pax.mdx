---
title: "Create PAX"
api: "POST /org/create/pax"
description: "Create a new PAX (Platform Access eXtension) within the organization"
---

Create a new PAX (Platform Access eXtension) within your organization for managing platform integrations, extensions, and custom functionality. This endpoint allows you to set up PAX modules with different types and configurations.

<Note>
  **Console API Endpoint**
  
  This endpoint is part of the Console API category and requires Bearer Token authentication. It's designed for PAX management and platform extension development within the Weir AI platform.
</Note>

## Authentication

This endpoint requires Bearer Token authentication. Include your JWT token in the Authorization header:

```bash
Authorization: Bearer <your_jwt_token>
```

## Request

<ParamField body="name" type="string" required>
  Name of the PAX to create
  
  **Example**: "Custom Analytics Extension"
  
  **Constraints**: 
  - Minimum length: 2 characters
  - Maximum length: 100 characters
  - Must be unique within the organization
  - Cannot contain special characters except spaces, hyphens, and underscores
</ParamField>

<ParamField body="teamId" type="string" required="false">
  ID of the team to associate with this PAX
  
  **Example**: "team_1234567890abcdef"
  
  **Constraints**: 
  - Must be a valid team ID within your organization
  - Team must exist and be accessible
  - If not provided, PAX will be associated with the user's default team
</ParamField>

<ParamField body="description" type="string" required="false">
  Description of the PAX's purpose and functionality
  
  **Example**: "Custom analytics extension for tracking user behavior and performance metrics"
  
  **Constraints**: 
  - Maximum length: 500 characters
  - Optional but recommended for documentation
</ParamField>

<ParamField body="type" type="string" required>
  Type of PAX being created
  
  **Options**: 
  - `Analytics`: Analytics and reporting extensions
  - `Integration`: Third-party service integrations
  - `Custom Function`: Custom business logic functions
  - `UI Component`: User interface components
  - `API Extension`: API endpoint extensions
  - `Data Processor`: Data processing and transformation
  - `Notification`: Notification and alerting systems
  - `Other`: Any other type of PAX
  
  **Example**: "Analytics"
</ParamField>

<ParamField body="platformId" type="string" required="false">
  ID of the platform this PAX extends
  
  **Example**: "platform_1234567890abcdef"
  
  **Constraints**: 
  - Must be a valid platform ID
  - Platform must exist in your organization
  - You must have access to the platform
</ParamField>

<ParamField body="version" type="string" required="false">
  Version of the PAX
  
  **Example**: "1.0.0"
  
  **Default**: "1.0.0"
  
  **Constraints**: 
  - Must follow semantic versioning (semver) format
  - Examples: "1.0.0", "2.1.3", "0.1.0-beta"
</ParamField>

<ParamField body="configuration" type="object" required="false">
  PAX-specific configuration and settings
  
  **Properties**:
  - `enabled` (boolean): Whether the PAX is enabled
  - `auto_deploy` (boolean): Whether to auto-deploy on updates
  - `environment` (string): Environment for deployment
  - `dependencies` (array): List of required dependencies
  - `permissions` (object): Required permissions and access levels
  - `settings` (object): Custom configuration settings
  
  **Example**:
  ```json
  {
    "enabled": true,
    "auto_deploy": false,
    "environment": "production",
    "dependencies": ["react", "lodash", "moment"],
    "permissions": {
      "read_data": true,
      "write_data": false,
      "admin_access": false
    },
    "settings": {
      "tracking_enabled": true,
      "retention_days": 90,
      "export_format": "json"
    }
  }
  ```
</ParamField>

<ParamField body="code" type="object" required="false">
  PAX code and implementation details
  
  **Properties**:
  - `language` (string): Programming language used
  - `entry_point` (string): Main entry point file
  - `source_files` (array): List of source files
  - `build_commands` (array): Build commands to execute
  - `test_commands` (array): Test commands to execute
  
  **Example**:
  ```json
  {
    "language": "javascript",
    "entry_point": "index.js",
    "source_files": ["index.js", "utils.js", "config.js"],
    "build_commands": ["npm install", "npm run build"],
    "test_commands": ["npm test"]
  }
  ```
</ParamField>

<ParamField body="tags" type="array" required="false">
  Tags for categorizing and organizing the PAX
  
  **Example**: ["analytics", "tracking", "production"]
  
  **Constraints**: 
  - Maximum 10 tags per PAX
  - Each tag maximum 50 characters
  - Tags are case-insensitive
</ParamField>

<ParamField body="documentation" type="object" required="false">
  Documentation and usage information
  
  **Properties**:
  - `overview` (string): Overview of the PAX functionality
  - `usage_examples` (array): Usage examples and code snippets
