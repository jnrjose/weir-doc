Welcome to the Weir AI API Playground! This interactive environment allows you to test all API endpoints directly in your browser without needing external tools like Postman or curl.

<Info>
  **Interactive Testing**
  
  Use this playground to explore endpoints, test different parameters, and understand API responses. All endpoints are fully functional and will make real API calls.
</Info>

## How to Use the Playground

<Steps>
  <Step title="Select an Endpoint" icon="mouse-pointer">
    Choose any endpoint from the API Reference section. Each endpoint has an interactive playground.
  </Step>
  <Step title="Configure Authentication" icon="key">
    Enter your API credentials in the authentication section of each endpoint.
  </Step>
  <Step title="Set Parameters" icon="cog">
    Fill in any required parameters, request body, or query parameters.
  </Step>
  <Step title="Make the Request" icon="play">
    Click "Try it out" to execute the API call and see the response.
  </Step>
  <Step title="View Results" icon="eye">
    Examine the response data, status codes, and headers.
  </Step>
</Steps>

## Authentication Setup

Before testing endpoints, you'll need to configure authentication:

### For External APIs
Use Basic Authentication with your username and password:

```json
{
  "username": "your_username",
  "password": "your_password"
}
```

### For Console/Admin APIs
Use Bearer Token authentication:

```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}
```

## Request/Response Examples

### Example 1: External API Token Generation

```bash Request
{`curl -X POST "https://external.example.com/auth/token" \\
  -H "Authorization: Basic dXNlcm5hbWU6cGFzc3dvcmQ=" \\
  -H "Content-Type: application/json"`}
```

```json Response
{
  "success": true,
  "data": {
    "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "token_type": "Bearer",
    "expires_in": 3600
  },
  "message": "Token generated successfully",
  "timestamp": "2024-01-15T10:30:00Z"
}
```

### Example 2: Create Team

```bash Request
{`curl -X POST "https://api.example.com/org/create/team" \\

  -H "Content-Type: application/json" \\

    "name": "Development Team"

}
```

## Error Handling in Playground

The playground will show you different types of errors you might encounter:

<CardGroup cols={2}>
  <Card title="Authentication Errors" icon="exclamation-triangle">
    - **401 Unauthorized**: Invalid credentials
    - **403 Forbidden**: Insufficient permissions
    - **Token Expired**: Need to refresh token
  </Card>
  <Card title="Validation Errors" icon="check-circle">
    - **400 Bad Request**: Invalid request data
    - **Missing Fields**: Required parameters not provided
    - **Invalid Format**: Data format validation errors
  </Card>
  <Card title="Resource Errors" icon="file-exclamation">
    - **404 Not Found**: Resource doesn't exist
    - **409 Conflict**: Resource already exists
    - **422 Unprocessable Entity**: Business logic validation
  </Card>
  <Card title="Rate Limiting" icon="clock">
    - **429 Too Many Requests**: Rate limit exceeded
    - **Retry After**: Information about when to retry
  </Card>
</CardGroup>
