# Core API Functionality: NIL Detection & Interaction

This document provides a detailed guide to a core use case of the Weir AI API: detecting Name, Image, and Likeness (NIL) usage within ad creatives. This functionality is central to ensuring compliance, managing talent usage rights, and automating the verification of ad content against licensing agreements. For engineering leads and their teams, understanding how to programmatically scan for and interpret NIL data is a key step in leveraging the full power of Weir AI. This section covers primary endpoints like `POST /v1/creatives/scan` as well as relevant "Public Services" endpoints such as `POST /ad/validateIdentity` that contribute to ad validation and potential NIL detection.

## Scanning Ad Creatives for NIL Content

The primary mechanism for NIL detection is by submitting an ad creative to our scanning engine. The engine will analyze the creative's content to identify any registered personas and check their usage against known licensing agreements. While `POST /v1/creatives/scan` is a dedicated endpoint for this, other "Public Services" endpoints can also be used for ad validation.

### Primary Endpoint: `POST /v1/creatives/scan`

This is a main endpoint you will use to initiate a NIL scan. It is an **asynchronous endpoint**, meaning you submit a request to start a scan, and Weir AI processes it in the background. You receive an immediate response confirming the scan has been queued, and the detailed results are delivered later, typically via a webhook (callback) or can be retrieved by polling a status endpoint.

#### Request Body Structure & Examples (for `/v1/creatives/scan`)
The request requires information about the creative to be scanned and can include optional metadata for tracking and context.

##### Request Parameters:

<Fields>
  <Field name="creative_url" type="string" required={true}>
    A publicly accessible URL to the ad creative content (e.g., an image URL, a video file URL, or a URL to an ad tag/HTML file). Weir AI will fetch the content from this URL for scanning.
    <Info>Alternative methods for submitting creative content (e.g., direct upload, base64 encoding) may be supported. Refer to **Section 4 (API Endpoint Reference)** for full details.</Info>
  </Field>
  <Field name="advertiser_id" type="string" required={false}>
    An internal identifier from your system for the advertiser associated with this creative. Useful for tracking, reporting, and context-aware analysis.
  </Field>
  <Field name="campaign_id" type="string" required={false}>
    An internal identifier from your system for the campaign this creative belongs to.
  </Field>
  <Field name="callback_url" type="string" required={false} recommended={true}>
    A URL to which Weir AI will send a POST request (a webhook) with the full scan results once the scan is complete. Using callbacks is far more efficient than repeatedly polling for results.
  </Field>
</Fields>

##### Request Body Example (for `/v1/creatives/scan`):
```json POST /v1/creatives/scan - Request Body
  "creative_url": "https://your-ad-cdn.com/creatives/awesomerobotad-123.jpg",
  "advertiser_id": "adv-9876",
  "campaign_id": "cmp-summer-sale-2025",
  "callback_url": "https://your-backend.example.com/api/weir-nil-results"
```

### Understanding the Scan Response
The API provides two levels of response for the `/v1/creatives/scan` endpoint: the immediate response to your `POST` request and the final, detailed scan result (delivered via webhook or retrieved from a status endpoint). Responses from `/ad/validation/status` would follow a similar pattern of conveying results upon completion.

#### 1. Immediate Response (`202 Accepted` for `/v1/creatives/scan`)
When you successfully submit a scan request to `/v1/creatives/scan`, you'll receive an HTTP `202 Accepted` status code. The body of this response confirms that your scan has been successfully queued.

```json Example 202 Accepted Response Body (for /v1/creatives/scan)
  "scan_id": "scn_a1b2c3d4e5f6g7h8",
  "status": "QUEUED",
  "message": "Creative scan accepted and queued for processing. Results will be sent to the provided callback_url upon completion.",
  "status_check_endpoint": "/v1/creatives/scans/scn_a1b2c3d4e5f6g7h8"
```
<AccordionGroup>
  <Accordion title="Key fields in the immediate response:" icon="Key" defaultOpen={true}>
    - **`scan_id` (String):** Crucial unique identifier for the scan job. Engineering teams should log this ID.
    - **`status_check_endpoint` (String):** A relative URL to poll for scan status if not using a callback.
  </Accordion>
</AccordionGroup>

#### 2. Final Scan Result (Delivered to your `callback_url` for `/v1/creatives/scan`)
This is the detailed result of the completed scan from `/v1/creatives/scan`. It will be a `POST` request from Weir AI to your specified `callback_url` with a JSON body.

### Interpreting Persona and License Objects in the Response

When NIL matches are found (whether from `/v1/creatives/scan` or as part of the results from `/ad/validation/status`), the `persona` and `license` objects contain critical information. Here's a breakdown of what to look for:

<AccordionGroup>
    <Accordion title="`persona` Object Details" icon="User" defaultOpen={true}>
        <Fields>
            <Field name="persona_id" type="string">
                Unique identifier for the detected individual in Weir AI.
            </Field>
            <Field name="name" type="string">
                The full name of the detected individual.
            </Field>
            <Field name="category" type="string">
                The category of the individual (e.g., Athlete, Musician, Actor, Influencer).
            </Field>
            <Field name="confidence_score" type="number">
                A numeric value (0.0–1.0) representing the detection confidence. Recommended threshold: > 0.90.
            </Field>
        </Fields>
    </Accordion>
    <Accordion title="`license` Object Details" icon="Certificate" defaultOpen={true}>
        <Fields>
            <Field name="license_id" type="string">
                Unique identifier for the specific license agreement.
            </Field>
            <Field name="is_active" type="boolean">
                Indicates whether the license is currently active.
            </Field>
            <Field name="is_compliant" type="boolean">
                Key field: Determines if the observed usage complies with license terms (e.g., advertiser, territory, date range).
            </Field>
            <Field name="usage_allowed" type="boolean">
                Simple flag indicating if any usage is permitted under this license.
            </Field>
            <Field name="start_date" type="string" format="date-time">
                ISO 8601 formatted effective start date of the license.
            </Field>
            <Field name="end_date" type="string" format="date-time">
                ISO 8601 formatted effective end date of the license.
            </Field>
            <Field name="allowed_advertisers" type="string[]">
                Array of advertiser IDs permitted to use this persona’s NIL.
            </Field>
            <Field name="territories" type="string[]">
                Array of geographic territories (ISO 3166-1 alpha-2 codes) where usage is permitted.
            </Field>
        </Fields>
    </Accordion>
    <Accordion title="`bounding_box` Object Details (Optional)" icon="Scan">
        If the match is visual, this object provides the coordinates and dimensions of the box surrounding the detected persona.
        <Fields>
            <Field name="top_left_x" type="number">
                X-coordinate of the top-left corner.
            </Field>
            <Field name="top_left_y" type="number">
                Y-coordinate of the top-left corner.
            </Field>
            <Field name="width" type="number">
                Width of the bounding box.
            </Field>
            <Field name="height" type="number">
                Height of the bounding box.
            </Field>
        </Fields>
    </Accordion>
</AccordionGroup>

### Code Examples for Making a Scan Request (Focus on `/v1/creatives/scan`)

Here are practical examples engineering teams can adapt to make a scan request to the `POST /v1/creatives/scan` endpoint. Similar principles would apply when constructing requests for `POST /ad/validateIdentity`, adjusting the endpoint path and request body as described above.

<CodeGroup>
  ```cURL"  bash 
    {`curl -X POST "https://api.weir.ai/v1/creatives/scan" \\
     -H "Authorization: Bearer <YOUR_API_KEY>" \\
     -H "Content-Type: application/json" \\
     -d '{
           "creative_url": "https://your-ad-cdn.com/creatives/alex-ray-ad.mp4",
           "advertiser_id": "adv-9876",
           "callback_url": "https://your-backend.example.com/api/weir-nil-results"
         }'`}
    ```
```python Python
import requests
import os
import json

# Best practice: store API key as an environment variable
API_KEY = os.getenv("WEIR_AI_API_KEY")
# Confirm the correct base URL for the endpoint you are targeting.
# For /v1/creatives/scan:
API_SCAN_ENDPOINT = "https://api.weir.ai/v1/creatives/scan"
# For /ad/validateIdentity (example, confirm actual base URL):
# API_VALIDATE_ENDPOINT = "https://api.weir.ai/ad/validateIdentity"

headers = {
    "Authorization": f"Bearer {API_KEY}",
    "Content-Type": "application/json"
}

# Payload for /v1/creatives/scan
payload_scan = {
    "creative_url": "https://your-ad-cdn.com/creatives/alex-ray-ad.mp4",
    "advertiser_id": "adv-9876",
    "callback_url": "https://your-backend.example.com/api/weir-nil-results"
}

# Example for /ad/validateIdentity (illustrative)
# payload_validate = {
#   "adName": "My Ad Creative",
#   "ad": "https://your-ad-cdn.com/creatives/my-creative.jpg"
# }

try:
    # Example for /v1/creatives/scan
    response = requests.post(API_SCAN_ENDPOINT, headers=headers, data=json.dumps(payload_scan))

    # Raise an exception for bad status codes (4xx or 5xx)
    response.raise_for_status()

    # On success (e.g., 202 Accepted), print the response content
    scan_confirmation = response.json()
    print("Scan successfully submitted (using /v1/creatives/scan):")
    print(f"  Scan ID: {scan_confirmation.get('scan_id')}")
    print(f"  Status: {scan_confirmation.get('status')}")
    if 'status_check_endpoint' in scan_confirmation:
        print(f"  Status Check: {API_SCAN_ENDPOINT.rsplit('/', 2)[0]}{scan_confirmation.get('status_check_endpoint')}")  # Construct full URL for status check

except requests.exceptions.HTTPError as http_err:
    print(f"HTTP error occurred: {http_err}")
    print("Response body:", response.text)
except Exception as err:
    print(f"An other error occurred: {err}")
```

      // The request was made but no response was received
      console.error('Network Error: No response received.', error.request);
    } else {
      // Something happened in setting up the request that triggered an Error
      console.error('Error:', error.message);

  });
