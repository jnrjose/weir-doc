# Interpreting Responses

Understanding how to properly interpret and handle API responses is crucial for building robust applications. This guide covers response patterns, error handling, data processing, and best practices for working with Weir API responses.

## Response Structure Overview

All Weir API responses follow a consistent structure:

```json
{
  "success": true,
  "data": {
    // Response data here
  },
  "message": "Operation completed successfully",
  "timestamp": "2024-01-15T10:30:00Z"
}
```

## HTTP Status Codes

### Success Codes

| Code | Meaning | Usage |
|------|---------|-------|
| `200` | OK | Successful GET, PUT, PATCH requests |
| `201` | Created | Successful POST requests |
| `204` | No Content | Successful DELETE requests |

### Client Error Codes

| Code | Meaning | Common Causes |
|------|---------|---------------|
| `400` | Bad Request | Invalid request format, missing required fields |
| `401` | Unauthorized | Invalid or missing authentication token |
| `403` | Forbidden | Insufficient permissions for the resource |
| `404` | Not Found | Resource doesn't exist or not accessible |
| `409` | Conflict | Resource already exists or conflict with current state |
| `422` | Unprocessable Entity | Validation errors, invalid data format |
| `429` | Too Many Requests | Rate limit exceeded |

### Server Error Codes

| Code | Meaning | Common Causes |
|------|---------|---------------|
| `500` | Internal Server Error | Unexpected server error |
| `502` | Bad Gateway | Server acting as gateway received invalid response |
| `503` | Service Unavailable | Server temporarily unavailable |
| `504` | Gateway Timeout | Server acting as gateway timed out |

## Response Processing Patterns

### Basic Response Handling

```javascript
async function handleAPIResponse(response) {
  // Check HTTP status
  if (!response.ok) {
    throw new Error(`HTTP error! status: ${response.status}`);
  }
  
  // Parse JSON
  const data = await response.json();
  
  // Check API success flag
  if (!data.success) {
    throw new Error(data.error.message);
  }
  
  return data.data;
}
```

### Comprehensive Error Handling

```javascript
class APIResponseHandler {
  static async handleResponse(response) {
    try {
      // Check HTTP status
      if (!response.ok) {
        await this.handleHTTPError(response);
      }
      
      // Parse JSON
      const data = await response.json();
      
      // Check API success flag
      if (!data.success) {
        this.handleAPIError(data.error);
      }
      
      return data.data;
    } catch (error) {
      console.error('Response handling failed:', error);
      throw error;
    }
  }
  
  static async handleHTTPError(response) {
    let errorMessage;
    
    switch (response.status) {
      case 400:
        errorMessage = 'Bad Request: Please check your request format';
        break;
      case 401:
        errorMessage = 'Unauthorized: Please check your authentication';
        break;
      case 403:
        errorMessage = 'Forbidden: You do not have permission to access this resource';
        break;
      case 404:
        errorMessage = 'Not Found: The requested resource does not exist';
        break;
      case 409:
        errorMessage = 'Conflict: The resource already exists or conflicts with current state';
        break;
      case 422:
        errorMessage = 'Validation Error: Please check your input data';
        break;
      case 429:
        errorMessage = 'Rate Limited: Please wait before making more requests';
        break;
      case 500:
        errorMessage = 'Internal Server Error: Please try again later';
        break;
      default:
        errorMessage = `Request failed with status ${response.status}`;
    }
    
    throw new Error(errorMessage);
  }
  
  static handleAPIError(error) {
    const errorMessages = {
      'VALIDATION_ERROR': 'Please check your input data',
      'AUTHENTICATION_FAILED': 'Invalid credentials provided',
      'INSUFFICIENT_PERMISSIONS': 'You do not have permission to perform this action',
      'RESOURCE_NOT_FOUND': 'The requested resource does not exist',
      'RATE_LIMIT_EXCEEDED': 'Too many requests. Please wait before trying again',
      'INTERNAL_ERROR': 'An internal error occurred. Please try again later'
    };
    
    const message = errorMessages[error.code] || error.message;
    throw new Error(message);
  }
}
```

## Data Processing Patterns

### Pagination Handling

```javascript
class PaginationHandler {
  static async loadAllPages(apiClient, endpoint, options = {}) {
    const allItems = [];
    let page = 1;
    let hasMore = true;
    
    while (hasMore) {
      try {
        const response = await apiClient.get(endpoint, {
          ...options,
          page,
          limit: 100 // Use maximum limit
        });
        
        allItems.push(...response.items);
        hasMore = response.pagination.hasNext;
        page++;
        
        // Add delay to respect rate limits
        if (hasMore) {
          await new Promise(resolve => setTimeout(resolve, 100));
        }
      } catch (error) {
        console.error(`Failed to load page ${page}:`, error);
        break;
      }
    }
    
    return allItems;
  }
  
  static createPaginationControls(pagination) {
    return {
      currentPage: pagination.page,
      totalPages: pagination.pages,
      totalItems: pagination.total,
      hasNext: pagination.hasNext,
      hasPrev: pagination.hasPrev,
      canGoNext: () => pagination.hasNext,
      canGoPrev: () => pagination.hasPrev
    };
  }
}
```

class DataTransformer {

      pagination: collectionData.pagination,

    };
  }

## Error Recovery Strategies

### Retry Logic

```javascript
class ErrorRecovery {
  static async withRetry(operation, maxRetries = 3, baseDelay = 1000) {
    for (let i = 0; i < maxRetries; i++) {
      try {
        return await operation();
      } catch (error) {
        if (i === maxRetries - 1) {
          throw error;
        }
        
        // Only retry on specific errors
        if (this.shouldRetry(error)) {
          const delay = baseDelay * Math.pow(2, i);
          await new Promise(resolve => setTimeout(resolve, delay));
          continue;
        }
        
        throw error;
      }
    }
  }
  
  static shouldRetry(error) {
    const retryableErrors = [
      'Rate Limited',
      'Internal Server Error',
      'Service Unavailable',
      'Gateway Timeout'
    ];
    
    return retryableErrors.some(errorType => 
      error.message.includes(errorType)
    );
  }
}
```

### Fallback Strategies

```javascript
class FallbackHandler {
  static async withFallback(primaryOperation, fallbackOperation) {
    try {
      return await primaryOperation();
    } catch (error) {
      console.warn('Primary operation failed, trying fallback:', error);
      
      try {
        return await fallbackOperation();
      } catch (fallbackError) {
        console.error('Fallback operation also failed:', fallbackError);
        throw new Error('Both primary and fallback operations failed');
      }
    }
  }
  
  static async withCacheFallback(apiOperation, cacheKey, cache) {
    try {
      const result = await apiOperation();
      cache.set(cacheKey, result);
      return result;
    } catch (error) {
      console.warn('API operation failed, using cache:', error);
      const cached = cache.get(cacheKey);
      
      if (cached) {
        return cached;
      }
      
      throw error;
    }
  }
}
```

## Response Validation

### Schema Validation

```javascript
class ResponseValidator {
  static validateTeamResponse(data) {
    const requiredFields = ['id', 'name', 'createdAt'];
    const missingFields = requiredFields.filter(field => !data[field]);
    
    if (missingFields.length > 0) {
      throw new Error(`Missing required fields: ${missingFields.join(', ')}`);
    }
    
    if (typeof data.memberCount !== 'number' || data.memberCount < 0) {
      throw new Error('Invalid member count');
    }
    
    return true;
  }
  
  static validatePaginationResponse(data) {
    if (!data.pagination) {
      throw new Error('Missing pagination information');
    }
    
    const requiredPaginationFields = ['page', 'limit', 'total', 'pages'];
    const missingFields = requiredPaginationFields.filter(
      field => data.pagination[field] === undefined
    );
    
    if (missingFields.length > 0) {
      throw new Error(`Missing pagination fields: ${missingFields.join(', ')}`);
    }
    
    return true;
  }
}
```

## Performance Optimization

### Response Caching

```javascript
class ResponseCache {
  constructor(ttl = 300000) { // 5 minutes
    this.cache = new Map();
    this.ttl = ttl;
  }
  
  get(key) {
    const item = this.cache.get(key);
    if (item && Date.now() - item.timestamp < this.ttl) {
      return item.data;
    }
    this.cache.delete(key);
    return null;
  }
  
  set(key, data) {
    this.cache.set(key, {
      data,
      timestamp: Date.now()
    });
  }
  
  clear() {
    this.cache.clear();
  }
  
  async getOrFetch(key, fetchFunction) {
    const cached = this.get(key);
    if (cached) {
      return cached;
    }
    
    const data = await fetchFunction();
    this.set(key, data);
    return data;
  }
}
```

### Response Streaming

```javascript
class StreamProcessor {
  static async processStream(response, processor) {
    const reader = response.body.getReader();
    const decoder = new TextDecoder();
    
    try {
      while (true) {
        const { done, value } = await reader.read();
        
        if (done) break;
        
        const chunk = decoder.decode(value);
        await processor(chunk);
      }
    } finally {
      reader.releaseLock();
    }
  }
}
```

## Best Practices Summary

### 1. Always Check Response Status
- Never assume a request was successful
- Handle all possible HTTP status codes
- Implement proper error handling

### 2. Validate Response Data
- Check for required fields
- Validate data types and formats
- Handle unexpected response structures

### 3. Implement Proper Error Handling
- Provide meaningful error messages
- Log errors for debugging
- Implement retry logic where appropriate

### 4. Optimize Performance
- Use response caching
- Implement pagination for large datasets
- Process data efficiently

### 5. Test Thoroughly
- Test success and error scenarios
- Validate response handling logic
- Test edge cases and error conditions
