# Console APIs

Console APIs are designed for Weir's internal console and dashboard applications. These APIs provide comprehensive access to platform management, organization administration, and user management capabilities.

## Overview

Console APIs are ideal for:
- Weir's internal dashboard applications
- Console management interfaces
- Administrative tools and utilities
- Platform monitoring and analytics
- User and organization management

## Authentication

Console APIs use Bearer token authentication with a special header:

```bash
curl -X GET "https://api-dev.weir.ai/org/teams" \
  -H "Authorization: Bearer your-console-token" \
  -H "x-source: console"
```

## Rate Limits

Console APIs have the following rate limits:
- **5,000 requests per hour** per console user
- **500 requests per minute** burst limit
- **50 concurrent requests** maximum

<Callout type="info">
Console APIs have higher rate limits compared to external APIs due to their internal nature.
</Callout>

## Required Headers

All console API requests must include:

```bash
Authorization: Bearer your-console-token
x-source: console
Content-Type: application/json
```

## Error Handling

Console APIs return detailed error information:

```json
{
  "success": false,
  "error": {
    "code": "INSUFFICIENT_PERMISSIONS",
    "message": "Insufficient permissions for this operation",
    "details": "You need admin-level permissions to perform this action"
  },
  "timestamp": "2024-01-15T10:30:00Z"
}
```

## Common Error Codes

| Code | Description | Solution |
|------|-------------|----------|
| `INSUFFICIENT_PERMISSIONS` | User lacks required permissions | Check user role and permissions |
| `INVALID_SOURCE_HEADER` | Missing or invalid x-source header | Include `x-source: console` header |
| `TOKEN_EXPIRED` | Console token has expired | Refresh the token |
| `RATE_LIMIT_EXCEEDED` | Too many requests | Wait before making another request |
| `RESOURCE_NOT_FOUND` | Requested resource doesn't exist | Check resource ID and permissions |

## Best Practices

### 1. Include Required Headers
```javascript
async function makeConsoleRequest(endpoint, options = {}) {
  const response = await fetch(`https://api-dev.weir.ai${endpoint}`, {
    ...options,
    headers: {
      'Authorization': `Bearer ${consoleToken}`,
      'x-source': 'console',
      'Content-Type': 'application/json',
      ...options.headers
    }
  });
  
  return response;
}
```

### 2. Handle Permission Errors
```javascript
async function safeConsoleRequest(endpoint, options = {}) {
  try {
    const response = await makeConsoleRequest(endpoint, options);
    
    if (response.status === 403) {
      const error = await response.json();
      if (error.error.code === 'INSUFFICIENT_PERMISSIONS') {
        throw new Error('You do not have permission to perform this action');
      }
    }
    
    return response;
  } catch (error) {
    console.error('Console API request failed:', error);
    throw error;
  }
}
```

### 3. Implement Retry Logic
```javascript
async function makeRequestWithRetry(endpoint, options = {}, maxRetries = 3) {
  for (let i = 0; i < maxRetries; i++) {
    try {
      const response = await makeConsoleRequest(endpoint, options);
      
      if (response.status === 429) {
        const retryAfter = response.headers.get('Retry-After') || 60;
        console.log(`Rate limited. Retrying after ${retryAfter} seconds...`);
        await new Promise(resolve => setTimeout(resolve, retryAfter * 1000));
        continue;
      }
      
      return response;
    } catch (error) {
      if (i === maxRetries - 1) throw error;
      await new Promise(resolve => setTimeout(resolve, 1000 * Math.pow(2, i)));
    }
  }
}
```

## Security Considerations

<Callout type="warning">
**Important Security Notes:**

- Console tokens should only be used in secure, internal environments
- Never expose console tokens in client-side code
- Implement proper access controls and user permissions
- Use HTTPS for all console API requests
- Regularly rotate console tokens
</Callout>
