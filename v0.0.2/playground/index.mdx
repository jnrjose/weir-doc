## Authentication

The playground supports multiple authentication methods:

### 1. API Key Authentication
```bash
# Generate access token
curl -X POST "https://api-dev.weir.ai/auth/token" \
  -u "your-client-id:your-secret-key"
```

### 2. Bearer Token Authentication
```bash
# Use access token
curl -X GET "https://api-dev.weir.ai/org/information" \
  -H "Authorization: Bearer your-access-token"
```

### 3. Console Authentication
```bash
# Console API with special header
curl -X GET "https://api-dev.weir.ai/org/teams" \
  -H "Authorization: Bearer your-console-token" \
  -H "x-source: console"
```

## Rate Limits

The playground respects the same rate limits as the actual API:

| API Category | Rate Limit | Window |
|--------------|------------|--------|
| External APIs | 1,000 requests | Per hour |
| Console APIs | 5,000 requests | Per hour |
| Admin APIs | 10,000 requests | Per hour |

## Error Handling

The playground includes comprehensive error handling examples:

### Common Error Scenarios
- **Authentication failures** with invalid credentials
- **Rate limiting** with retry logic

## Best Practices

### 1. Test Authentication First
Always start by testing your authentication method before making other API calls.

### 2. Use Appropriate Endpoints
Choose the right API category for your use case:
- **External APIs** for third-party integrations
- **Console APIs** for internal applications
- **Admin APIs** for administrative functions

### 3. Handle Errors Gracefully
Implement proper error handling in your applications based on the playground examples.

### 4. Respect Rate Limits
Use the playground to understand rate limits and implement appropriate throttling.
