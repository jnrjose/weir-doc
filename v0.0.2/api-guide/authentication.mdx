# Authentication Guide

Weir provides a comprehensive authentication system designed to support various integration scenarios while maintaining security and ease of use.

## Authentication Methods

Weir supports multiple authentication methods depending on your use case:

<Tabs>
  <Tab title="API Key Authentication">
    <Callout type="info">
    **Best for**: External integrations, third-party applications, and automated systems
    </Callout>

    API Key authentication uses your Client ID and Secret Key to obtain access tokens.

    ### Getting Your Credentials

    1. Log into your Weir dashboard
    2. Navigate to **Settings** → **API Keys**
    3. Generate a new API key pair
    4. Copy your **Client ID** and **Secret Key**

    ### Making Authenticated Requests

    ```bash
    # Step 1: Get an access token
    curl -X POST "https://api-dev.weir.ai/auth/token" \
      -u "your-client-id:your-secret-key"
    ```

    **Response:**
    ```json
    {
      "success": true,
      "data": {
        "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
        "expiresIn": 3600,
        "tokenType": "Bearer"
      }
    }
    ```

    ```bash
    # Step 2: Use the token in subsequent requests
    curl -X GET "https://api-dev.weir.ai/org/information" \
      -H "Authorization: Bearer your-access-token"
    ```

  </Tab>
  <Tab title="User Authentication">
    <Callout type="info">
    **Best for**: User-facing applications, web dashboards, and mobile apps
    </Callout>

    User authentication allows individual users to authenticate and access their organization's resources.

    ### Login Process

    ```bash
    curl -X POST "https://api-dev.weir.ai/auth/login" \
      -H "Content-Type: application/json" \
      -d '{
        "username": "user@example.com",
        "password": "your-password"
      }'
    ```

    **Response:**
    ```json
    {
      "success": true,
      "data": {
        "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
        "refreshToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
        "expiresIn": 3600,
        "user": {
          "id": "user-123",
          "email": "user@example.com",
          "role": "Organization_User"
        }
      }
    }
    ```

    ### Token Refresh

    Access tokens expire after 1 hour. Use the refresh token to get a new access token:

    ```bash
    curl -X POST "https://api-dev.weir.ai/auth/refresh/token" \
      -H "Content-Type: application/json" \
      -d '{
        "refreshToken": "your-refresh-token"
      }'
    ```

  </Tab>
  <Tab title="Console Authentication">
    <Callout type="info">
    **Best for**: Internal console applications and administrative tools
    </Callout>

    Console authentication is designed for Weir's internal dashboard and administrative interfaces.

    ### Console Headers

    Console requests require a special header to identify the source:

    ```bash
    curl -X GET "https://api-dev.weir.ai/org/teams" \
      -H "Authorization: Bearer your-console-token" \
      -H "x-source: console"
    ```

    ### Console-Specific Features

    - Higher rate limits
    - Access to administrative functions
    - Organization management capabilities
    - Team and user management

  </Tab>
  <Tab title="Admin Authentication">
    <Callout type="info">
    **Best for**: System administrators and platform-wide operations
    </Callout>

    Admin authentication provides access to system-wide administrative functions.

    ### Admin Login

    ```bash
    curl -X POST "https://api-dev.weir.ai/auth/authenticateAdmin" \
      -H "Content-Type: application/json" \
      -d '{
        "token": "admin-token"
      }'
    ```

    ### Admin Capabilities

    - System-wide user management
    - Platform configuration
    - License management
    - Log access and monitoring
    - Pod management

  </Tab>

## Token Management

### Access Tokens

Access tokens are short-lived (1 hour) and used for API requests:

```json
{
  "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "expiresIn": 3600,
  "tokenType": "Bearer"
}
```

### Refresh Tokens

Refresh tokens are long-lived and used to obtain new access tokens:

```json
{
  "refreshToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "expiresIn": 2592000
}
```

### Token Security

<Callout type="warning">
**Important Security Considerations:**

- Store tokens securely (use environment variables or secure key management)
- Never expose tokens in client-side code
- Implement token refresh logic to handle expiration
- Use HTTPS for all API requests
- Rotate API keys regularly
</Callout>

## Error Handling

### Authentication Errors

| Error Code | Description | Solution |
|------------|-------------|----------|
| `INVALID_CREDENTIALS` | Wrong username/password | Verify credentials |
| `TOKEN_EXPIRED` | Access token has expired | Refresh the token |
| `INVALID_TOKEN` | Malformed or invalid token | Re-authenticate |
| `INSUFFICIENT_PERMISSIONS` | Token lacks required permissions | Check user role |
| `ACCOUNT_LOCKED` | Account is temporarily locked | Contact support |

### Example Error Response

```json
{
  "success": false,
  "error": {
    "code": "TOKEN_EXPIRED",
    "message": "Access token has expired",
    "details": "Please refresh your token or re-authenticate"
  },
  "timestamp": "2024-01-15T10:30:00Z"
}
```

## Best Practices

### 1. Implement Token Refresh

```javascript
async function makeAuthenticatedRequest(url, options = {}) {
  try {
    const response = await fetch(url, {
      ...options,
      headers: {
        'Authorization': `Bearer ${accessToken}`,
        ...options.headers
      }
    });
    
    if (response.status === 401) {
      // Token expired, refresh it
      await refreshAccessToken();
      // Retry the request
      return makeAuthenticatedRequest(url, options);
    }
    
    return response;
  } catch (error) {
    console.error('Request failed:', error);
    throw error;
  }
}
```

### 2. Handle Rate Limits

```javascript
async function makeRequestWithRetry(url, options = {}, maxRetries = 3) {
  for (let i = 0; i < maxRetries; i++) {
    try {
      const response = await fetch(url, options);
      
      if (response.status === 429) {
        // Rate limited, wait and retry
        const retryAfter = response.headers.get('Retry-After') || 60;
        await new Promise(resolve => setTimeout(resolve, retryAfter * 1000));
        continue;
      }
      
      return response;
    } catch (error) {
      if (i === maxRetries - 1) throw error;
      await new Promise(resolve => setTimeout(resolve, 1000 * Math.pow(2, i)));
    }
  }
}
```

### 3. Secure Storage

```javascript
// Store tokens securely
const secureStorage = {
  setToken: (token) => {
    // Use secure storage mechanism
    localStorage.setItem('weir_token', token);
  },
  
  getToken: () => {
    return localStorage.getItem('weir_token');
  },
  
  clearToken: () => {
    localStorage.removeItem('weir_token');
  }
};
```

## Troubleshooting

### Common Issues

**Q: I'm getting "Invalid credentials" errors**
A: Double-check your Client ID and Secret Key. Make sure there are no extra spaces or characters.

**Q: My token keeps expiring**
A: Implement automatic token refresh using the refresh token endpoint.

**Q: I'm getting permission denied errors**
A: Check your user role and ensure you have the necessary permissions for the requested operation.

**Q: Rate limit errors**
A: Implement exponential backoff and respect the Retry-After header.
