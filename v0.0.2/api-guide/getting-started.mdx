# Getting Started with Weir API

Welcome to Weir's comprehensive API documentation! This guide will help you get up and running quickly with our NIL (Name, Image, Likeness) detection and identity verification platform.

## What You'll Learn

By the end of this guide, you'll understand:
- How to authenticate with the Weir API using multiple methods
- How to make your first API request with proper error handling
- The complete structure of our API responses and error formats
- How to handle rate limits, pagination, and edge cases
- Best practices for integrating Weir into your applications
- How to use our interactive playground for testing

## Prerequisites

Before you begin, make sure you have:
- A Weir account (sign up at [weir.ai](https://weir.ai))
- Your API credentials (Client ID and Secret Key)
- Basic knowledge of HTTP and REST APIs
- A development environment ready for API integration

## Authentication Methods

Weir supports multiple authentication methods depending on your use case:

### 1. API Key Authentication
For external integrations and third-party applications:

```bash
curl -X POST "https://api-dev.weir.ai/auth/token" \
  -u "your-client-id:your-secret-key"
```

### 2. Bearer Token Authentication
For authenticated user sessions:

```bash
curl -X GET "https://api-dev.weir.ai/org/information" \
  -H "Authorization: Bearer your-access-token"
```

### 3. Console Authentication
For internal console applications:

```bash
curl -X GET "https://api-dev.weir.ai/org/teams" \
  -H "Authorization: Bearer your-console-token" \
  -H "x-source: console"
```

## Making Your First Request

Let's start with a simple request to get organization information:

```bash
# Step 1: Get an access token
curl -X POST "https://api-dev.weir.ai/auth/token" \
  -u "your-client-id:your-secret-key"

# Step 2: Use the token to make a request
curl -X GET "https://api-dev.weir.ai/org/information" \
  -H "Authorization: Bearer your-access-token"
```

## Understanding API Responses

All Weir API responses follow a consistent format:

```json
{
  "success": true,
  "data": {
    // Your requested data here
  },
  "message": "Operation completed successfully",
  "timestamp": "2024-01-15T10:30:00Z"
}
```

### Response Fields

| Field | Type | Description |
|-------|------|-------------|
| `success` | boolean | Indicates if the request was successful |
| `data` | object | The requested data (varies by endpoint) |
| `message` | string | Human-readable message about the operation |
| `timestamp` | string | ISO 8601 timestamp of the response |

## Error Handling

When something goes wrong, Weir returns detailed error information:

```json
{
  "success": false,
  "error": {
    "code": "AUTHENTICATION_FAILED",
    "message": "Invalid credentials provided",
    "details": "The provided API key is invalid or expired"
  },
  "timestamp": "2024-01-15T10:30:00Z"
}
```

### Common Error Codes

| Code | Description | Action |
|------|-------------|--------|
| `AUTHENTICATION_FAILED` | Invalid or missing credentials | Check your API keys |
| `INVALID_REQUEST` | Malformed request | Validate your request format |
| `RATE_LIMIT_EXCEEDED` | Too many requests | Implement rate limiting |
| `RESOURCE_NOT_FOUND` | Requested resource doesn't exist | Check your endpoint URL |
| `PERMISSION_DENIED` | Insufficient permissions | Verify your access level |

## Rate Limits

Weir implements rate limiting to ensure fair usage:

- **External APIs**: 1000 requests per hour per API key
- **Console APIs**: 5000 requests per hour per user
- **Admin APIs**: 10000 requests per hour per admin user

<Callout type="warning">
Rate limits are enforced per API key or user. Exceeding limits will result in a 429 status code.
</Callout>
