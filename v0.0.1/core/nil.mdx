This chapter details the Weir AI trial and ad demonstration workflow. This process is designed to showcase the platform's capabilities by allowing a user to register, upload their own image (a "selfie"), and receive newly generated advertisements featuring that image. For engineering leads and their teams, this provides a clear, three-step path to demonstrate a core value proposition of the platform. After generating these ads, your application can then submit them to Weir AI's validation and NIL (Name, Image, Likeness) detection services to analyze the content for compliance and licensing details.

<Info>The entire workflow uses the base URL: `https://api-dev.weir.ai`.</Info>

## Part 1: The Ad Demo Workflow

This workflow consists of three distinct API calls: registering the user, uploading an image, and retrieving the generated ads.

<Steps>
  <Step title="1. Registration" icon="User-Plus">
    The first step is to create a trial user account. This action provides the necessary authentication tokens for subsequent steps.
    <br/>
    **Endpoint:** `POST /gateway/ui/trial/register`
    <br/>
    **Purpose:** Creates a new trial user and returns an access token required for protected endpoints.

    **Request Body Structure:**
    Your application will send a JSON object containing the user's details.
    <Fields>
      <Field name="firstname" type="string" required={true}>
        The first name of the user.
      </Field>
      <Field name="email" type="string" required={true}>
        The user's email address.
      </Field>
      <Field name="demoConsent" type="boolean" required={true}>
        A flag indicating the user's consent for the demo.
      </Field>
      <Field name="fakeAdEmailOptIn" type="boolean" required={true}>
        A flag for opting into receiving fake ad emails.
      </Field>
    </Fields>

    **Example Request Body:**
    ```json
    {
      "firstname": "Alex",
      "email": "alex.engineer@example.com",
      "demoConsent": true,
      "fakeAdEmailOptIn": false
    }
    ```

    **Understanding the Response:**
    A successful registration returns a `201 Created` status. The response body includes user information, a critical `accessToken`, and a `refreshToken`. Your application must securely store the `accessToken` to authenticate the user for the next steps.

    **Example `201 Created` Response:**
    ```json
    {
      "status": "success",
      "message": "Registration was successful",
      "data": {
        "user": {
          "sub": "683f7ddd7ba018e9b4346acb",
          "firstname": "Alex",
          "email": "alex.engineer@example.com",
          "hasExistingProfile": false
        },
        "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
        "refreshToken": "djA6NjgzZjdkZDc3YmEwMThlOWI0MzQ2YWNi..."
      }
    }
    ```
  </Step>

  <Step title="2. Image Upload" icon="Upload">
    With the `accessToken` from the registration step, your application can now upload a user's image.
    <br/>
    **Endpoint:** `POST /gateway/ui/trial/upload-selfie`
    <br/>
    **Purpose:** Uploads a user's image, which will be used to generate personalized ad creatives.
    <br/>
    **Authentication:** This is a protected endpoint and requires Bearer Token authentication. Your application must include the `accessToken` in the `Authorization` header.
    <br/>
    **Header Format:** `Authorization: Bearer <accessToken>`

    **Request Body Structure:**
    The request is sent as `multipart/form-data` and contains the image file.
    <Fields>
      <Field name="image" type="binary (file)" required={true}>
        The user's image file.
      </Field>
    </Fields>

    **Understanding the Response:**
    A successful upload returns a `201 Created` status. The response body contains a `data` field with a `requestId` string. This `requestId` is the unique identifier for the uploaded image and the subsequent ad generation job. Your application must store this ID for the final step.

    **Example `201 Created` Response:**
    ```json
    {
      "status": "success",
      "message": "Image uploaded successfully",
      "data": "OSo5op28"
    }
    ```
  </Step>

  <Step title="3. Get Generated Ads" icon="Images">
    Using the `requestId` from the image upload, your application can now retrieve the URLs of the personalized ads.
    <br/>
    **Endpoint:** `GET /gateway/ui/trial/fakeads/{requestId}`
    <br/>
    **Purpose:** Retrieves a list of URLs for the generated ad creatives.
    <br/>
    **Authentication:** Although not explicitly marked in the spec, this endpoint accesses a user-specific resource and requires the same Bearer Token authentication as the upload step.
    <br/>
    **Header Format:** `Authorization: Bearer <accessToken>`
    <br/>
    **Path Parameter:** The `requestId` from the previous step is included in the URL path.

    **Understanding the Response:**
    A successful request returns a `200 OK` status when the ad generation is complete. The response body contains an array of strings, where each string is a URL pointing to a generated ad.
    <Note>If the ads are not yet ready, the API may return a different status or message indicating the process is still pending.</Note>

    **Example `200 OK` Response:**
    ```json
    {
      "status": "success",
      "message": "Ad generation completed",
      "data": [
        "[https://api-dev.weir.ai/gateway/ui/trial/fakead/68307b7e73c815b31f8e7e6d](https://api-dev.weir.ai/gateway/ui/trial/fakead/68307b7e73c815b31f8e7e6d)",
        "[https://api-dev.weir.ai/gateway/ui/trial/fakead/683079ce554aee42d950a969](https://api-dev.weir.ai/gateway/ui/trial/fakead/683079ce554aee42d950a969)"
      ]
    }
    ```
  </Step>
</Steps>

## Part 2: Analyzing Generated Ads for NIL Content

After your application has retrieved the URLs of the generated ads from the demo workflow, the next logical step is to analyze these new creatives for NIL content and compliance. Your application will use the ad validation endpoints for this purpose.

### Submitting Generated Ads for NIL Analysis
You will take the ad URLs returned from the `GET /gateway/ui/trial/fakeads/{requestId}` endpoint and submit them, one by one, to the ad validation endpoint.

**Endpoint:** `POST /ad/validateIdentity`
<br/>
**Purpose:** Submits an ad for a comprehensive identity and NIL compliance scan.
<br/>
**Process:** This is an asynchronous process. You submit the ad URL, receive a `trackingId`, and then use that ID to poll for the results using `GET /ad/validation/status`.

<Tip>For full details on the `POST /ad/validateIdentity` and `GET /ad/validation/status` two-step process, refer to the **"Core API Functionality: NIL Detection & Interaction"** documentation chapter (artifact ID: `weir_ai_core_nil_functionality`).</Tip>

### Understanding the Scan Response
When you retrieve the final validation status from `GET /ad/validation/status`, the response will detail any NIL matches.

<AccordionGroup>
  <Accordion title="Successful scan with NIL matches" icon="Users">
    The response will contain a `nil_matches` array with one or more objects. Each object provides details about the detected `persona` and their associated `license`.
  </Accordion>
  <Accordion title="Successful scan with no NIL matches" icon="User-Minus">
    The `nil_matches` array will be empty.
  </Accordion>
  <Accordion title="Error responses" icon="triangle-exclamation">
    If the validation fails or the request is invalid, the API will return a standard error response.
  </Accordion>
</AccordionGroup>

### Interpreting Persona and License Objects in the Response
When NIL matches are found, your application will parse the `persona` and `license` objects to understand the compliance status.

<Accordion title="`persona` Object" icon="User" defaultOpen={true}>
  Contains the ID, name, and category of the detected individual, along with a confidence score for the match.
</Accordion>
<Accordion title="`license` Object" icon="Certificate" defaultOpen={true}>
  Contains the license ID and its terms, such as the active date range, allowed advertisers, and geographic territories. Critically, it includes an `is_compliant` boolean field, which provides Weir AI's determination of whether the ad's usage complies with the known license terms.
</Accordion>

import requests
import os
import time
import json

API_BASE_URL = "[https://api-dev.weir.ai](https://api-dev.weir.ai)"

def register_user(email, first_name):
    """Registers a user and returns the access token."""
    payload = {
        "firstname": first_name,
        "email": email,
        "demoConsent": True,
        "fakeAdEmailOptIn": False
    }
    response = requests.post(f"{API_BASE_URL}/gateway/ui/trial/register", json=payload)
    response.raise_for_status()
    return response.json()["data"]["accessToken"]

def upload_selfie(token, image_path):
    """Uploads an image and returns a requestId."""
    headers = {"Authorization": f"Bearer {token}"}
    with open(image_path, "rb") as image_file:
        files = {"image": (os.path.basename(image_path), image_file)}
        response = requests.post(
            f"{API_BASE_URL}/gateway/ui/trial/upload-selfie",
            headers=headers,
            files=files
        )
        response.raise_for_status()
        return response.json()["data"]  # This is the requestId

def get_fake_ads(token, request_id):
    """Retrieves generated ad URLs."""
    headers = {"Authorization": f"Bearer {token}"}
    # Polling may be required in a real-world scenario if ads aren't ready immediately
    response = requests.get(
        f"{API_BASE_URL}/gateway/ui/trial/fakeads/{request_id}",
        headers=headers
    )
    response.raise_for_status()
    return response.json()["data"]  # This is the array of ad URLs

# --- Main Execution ---
try:
    print("Step 1: Registering user...")
    access_token = register_user("alex.python.demo@example.com", "Alex")
    print(f"Registration successful. Token starts with: {access_token[:15]}...")

    print("\nStep 3: Retrieving generated ads (waiting 15 seconds)...")

  package main

import (
	bytes "bytes"
	encoding/json"
	fmt"
	io"
	mime/multipart"
	net/http"
	os"
	path/filepath"
	time"
)

const (
	apiBaseURL = "https://api-dev.weir.ai"
)

// registerUser registers a user and returns the access token.
func registerUser(email, firstName string) (string, error) {
	url := fmt.Sprintf("%s/gateway/ui/trial/register", apiBaseURL)
	payload := map[string]interface{}{
		"firstname":         firstName,
		"email":             email,
		"demoConsent":       true,
		"fakeAdEmailOptIn":  false,
	}
	bodyBytes, err := json.Marshal(payload)
	if err != nil {
		return "", fmt.Errorf("failed to marshal payload: %w", err)
	}

	req, err := http.NewRequest(http.MethodPost, url, bytes.NewBuffer(bodyBytes))
	if err != nil {
		return "", fmt.Errorf("failed to create request: %w", err)
	}
	req.Header.Set("Content-Type", "application/json")

	client := &http.Client{}
	resp, err := client.Do(req)
	if err != nil {
		return "", fmt.Errorf("registration request failed: %w", err)
	}
	defer resp.Body.Close()

	if resp.StatusCode != http.StatusCreated && resp.StatusCode != http.StatusOK {
		body, _ := io.ReadAll(resp.Body)
		return "", fmt.Errorf("unexpected status %d: %s", resp.StatusCode, string(body))
	}

	var result struct {
		Data struct {
			AccessToken string `json:"accessToken"`
		} `json:"data"`
	}
	if err := json.NewDecoder(resp.Body).Decode(&result); err != nil {
		return "", fmt.Errorf("failed to decode registration response: %w", err)
	}

	return result.Data.AccessToken, nil
}

// uploadSelfie uploads an image and returns a requestId.
func uploadSelfie(token, imagePath string) (string, error) {
	url := fmt.Sprintf("%s/gateway/ui/trial/upload-selfie", apiBaseURL)

	file, err := os.Open(imagePath)
	if err != nil {
		return "", fmt.Errorf("failed to open image file: %w", err)
	}
	defer file.Close()

	body := &bytes.Buffer{}
	writer := multipart.NewWriter(body)
	part, err := writer.CreateFormFile("image", filepath.Base(imagePath))
	if err != nil {
		return "", fmt.Errorf("failed to create form file: %w", err)
	}
	if _, err := io.Copy(part, file); err != nil {
		return "", fmt.Errorf("failed to copy file content: %w", err)
	}
	writer.Close()

	req, err := http.NewRequest(http.MethodPost, url, body)
	if err != nil {
		return "", fmt.Errorf("failed to create upload request: %w", err)
	}
	req.Header.Set("Content-Type", writer.FormDataContentType())
	req.Header.Set("Authorization", fmt.Sprintf("Bearer %s", token))

	client := &http.Client{}
	resp, err := client.Do(req)
	if err != nil {
		return "", fmt.Errorf("upload request failed: %w", err)
	}
	defer resp.Body.Close()

	if resp.StatusCode != http.StatusCreated && resp.StatusCode != http.StatusOK {
		bodyBytes, _ := io.ReadAll(resp.Body)
		return "", fmt.Errorf("unexpected status %d: %s", resp.StatusCode, string(bodyBytes))
	}

	var result struct {
		Data string `json:"data"`
	}
	if err := json.NewDecoder(resp.Body).Decode(&result); err != nil {
		return "", fmt.Errorf("failed to decode upload response: %w", err)
	}

	return result.Data, nil
}

func getFakeAds(token, requestId string) ([]string, error) {
	url := fmt.Sprintf("%s/gateway/ui/trial/fakeads/%s", apiBaseURL, requestId)
	req, err := http.NewRequest(http.MethodGet, url, nil)
	if err != nil {
		return nil, fmt.Errorf("failed to create get request: %w", err)
	}
	req.Header.Set("Authorization", fmt.Sprintf("Bearer %s", token))

	client := &http.Client{}
	resp, err := client.Do(req)
	if err != nil {
		return nil, fmt.Errorf("get request failed: %w", err)
	}
	defer resp.Body.Close()

	if resp.StatusCode != http.StatusOK {
		body, _ := io.ReadAll(resp.Body)
		return nil, fmt.Errorf("unexpected status %d: %s", resp.StatusCode, string(body))
	}

	var result struct {
		Data []string `json:"data"`
	}
	if err := json.NewDecoder(resp.Body).Decode(&result); err != nil {
		return nil, fmt.Errorf("failed to decode get response: %w", err)
	}

	return result.Data, nil
}
