Welcome to the Weir AI API! This guide is designed to walk developers and engineering teams through the essential steps to begin integrating Weir AI's powerful capabilities into your applications. Our goal is to get you from initial onboarding to making your first successful, authenticated API call as smoothly and efficiently as possible. We understand your time is valuable, and clear, actionable steps are paramount.

## Overview of the Integration Workflow

Before diving into the specifics, let's look at the typical journey for integrating with Weir AI. This workflow outlines the key phases from initial organizational setup to actively using the API.

<Tip title="Conceptual Flow">
  A visual diagram would ideally represent this flow in the final documentation.
</Tip>

<Steps>
  <Step title="Platform Owner Onboards Organization" icon="building-user">
    An administrator from your company (referred to as the "Platform Owner" or "Org Admin") registers and configures your organization's account with Weir AI. This step establishes your company's presence on the platform.
  </Step>
  <Step title="Platform Owner Invites Developer" icon="user-plus">
    The Platform Owner invites individual developers or engineering team members to join the organization's Weir AI account. This grants developers access under the umbrella of the parent organization.
  </Step>
  <Step title="Developer Accepts Invitation & Creates Account" icon="envelope-open">
    The invited developer receives an email invitation, follows a link to accept, and either creates a new Weir AI developer account or links an existing one to this new organization.
  </Step>
  <Step title="Developer Accesses/Obtains API Key" icon="Key">
    Once the developer account is active within the organization, an API key is needed for authentication. This key is typically provisioned by the Platform Owner or made accessible through the Weir AI Developer Dashboard.
  </Step>
  <Step title="Developer Integrates API" icon="Code">
    With the API key, developers can now start making authenticated calls to Weir AI API endpoints. A common first functional step, particularly in AdTech contexts, might be to submit a creative for scanning using an endpoint like `POST /v1/creatives/scan`.
  </Step>
  <Step title="Developer Receives & Processes API Responses" icon="file-arrow-down">
    The application will receive responses from the API (e.g., scan job IDs, status updates, or direct results). These responses need to be parsed and handled according to the application's logic.
  </Step>
  <Step title="Developer Builds Features/Automations" icon="gear-complex-code">
    Leveraging the data and capabilities exposed by the API, developers can now build out the features, automations, or insights that the project requires.
  </Step>
</Steps>

This workflow provides a high-level map. The following sections will detail each relevant step for developers.

## Developer Oboarding and INitial Setup

Your journey as a developer with Weir AI begins with being invited to an organization and setting up your individual developer account.

### Understanding Roles: Platform Owner vs. Developer

Within the Weir AI ecosystem, there are typically distinct roles:

<AccordionGroup>
  <Accordion title="Platform Owner / Organization Administrator" icon="user-crown" defaultOpen={true}>
    This individual (or group) is responsible for the overall management of your company's organization within Weir AI.
    Their responsibilities usually include:
    - Initial organization setup and configuration.
    - Managing billing and subscription details.
    - Inviting developers and other users to the organization.
    - Potentially managing global API key provisioning or access policies.
    - Overseeing overall usage and security for the organization.
    Think of them as the primary administrative contact between your company and Weir AI.
  </Accordion>
  <Accordion title="Developer (Your Role)" icon="user-gear" defaultOpen={true}>
    As a developer, you are a technical user focused on integrating Weir AI APIs into your applications or workflows.
    Your primary interactions involve:
    - Using API keys to make authenticated requests.
    - Consulting API documentation (like this guide).
    - Building client-side logic to send requests and handle responses.
    - Implementing features based on Weir AI's capabilities.
    You typically operate under the umbrella of an organization established by a Platform Owner.
  </Accordion>
</AccordionGroup>

## API ACCESS & AUTHENTICATION

Securely authenticating your application's requests is fundamental. This is primarily done using API keys.

### Understanding API Keys: Purpose and Importance

<AccordionGroup>
  <Accordion title="Purpose" icon="Target">
    An API key is a unique secret token your application uses to identify itself and authenticate requests when calling Weir AI API endpoints.
  </Accordion>
  <Accordion title="Importance" icon="shield-check" defaultOpen={true}>
    - **Security:** Protects your organization's data and Weir AI resources from unauthorized access.
    - **Access Control:** Enables Weir AI to determine if your application has necessary permissions (authorization, often tied to key scopes).
    - **Usage Tracking & Billing:** Allows Weir AI to attribute API usage for monitoring, rate limiting, and billing.
  </Accordion>
</AccordionGroup>

<Warning>
  Treat your API keys with the same level of security as you would passwords or other sensitive credentials.
</Warning>

### Obtaining Your API Key

The method can vary based on your organization's setup:

    <Info>
      From the Developer Console you will be able to generate, manage, and view your own API keys directly from the 'API Keys' section of the Weir AI Developer Console."
    </Info>

**The moment you have your API key, its security is your responsibility.**

### Securely Storing and Using Your API Key (Best Practices Summary)

Protecting your API key is critical. Refer to **Section 3.2.1** for comprehensive API key security. Key practices:
- **NEVER** embed API keys directly in client-side code.
- **NEVER** commit API keys to version control.
- Use **Environment Variables** for server-side storage.
- Use **Secrets Management Systems** (e.g., HashiCorp Vault, AWS Secrets Manager) for production.
- Apply the **Principle of Least Privilege**.

## MAKING YOUR FIRST AUTHENTICATED CALL

Once your API key is securely set up (e.g., as an environment variable), you're ready for your first authenticated API call. This confirms your authentication works. For AdTech, a common first call is to `POST /v1/creatives/scan`.

### Example: First Call to `POST /v1/creatives/scan` using `curl`

This example submits a creative URL for scanning. Replace `<YOUR_API_KEY>` and `<YOUR_CREATIVE_URL>`.

<CodeBlock lang="bash">
  {`curl -X POST "https://api.weir.ai/v1/creatives/scan" \\
     -H "Authorization: Bearer <YOUR_API_KEY>" \\
     -H "Content-Type: application/json" \\
     -d '{
           "scan_request": {
             "creative_url": "<YOUR_CREATIVE_URL>",
             "callback_url": "https://your-system.example.com/weir-callback" # Optional
           },
           "scan_parameters": { # Optional
             "analysis_types": ["malware", "performance_metrics"] 
           }
         }'`}
</CodeBlock>

<Accordion title="Understanding the `curl` Command" icon="terminal">
  - `curl -X POST "https://api.weir.ai/v1/creatives/scan"`: Specifies POST method and endpoint URL. (Use correct base URL for your environment - Section 3.3.1).
  - `-H "Authorization: Bearer <YOUR_API_KEY>"`: Crucial authentication header.
  - `-H "Content-Type: application/json"`: Informs server of JSON request body.
  - `-d '{...}'`: JSON data payload.
    - `"scan_request"`: Details of the creative.
      - `"creative_url"`: URL of the ad creative. (See Section 4 for alternatives like direct content upload).
      - `"callback_url"` (Optional): For async notifications.
    - `"scan_parameters"` (Optional): Specifies analyses to perform (details in Section 4).
</Accordion>

### Expected Response
The exact response for `POST /v1/creatives/scan` depends on whether the operation is synchronous or asynchronous (detailed in Section 4).

<Tabs items={["Asynchronous (Common)", "Synchronous (Less Common)"]}>
  <Tab>
    You will likely receive an HTTP `202 Accepted`. The response body typically includes a `scan_id` or `job_id` to check status later (e.g., via `GET /v1/creatives/scan/status/{job_id}`) or await a callback.
    <CodeBlock lang="json" title="Example 202 Accepted Response">
      {`{
  "scan_id": "scn_abcdef1234567890",
  "status": "pending",
  "message": "Creative scan accepted and queued for processing.",
  "status_check_url": "https://api.weir.ai/v1/creatives/scan/status/scn_abcdef1234567890"
}`}
    </CodeBlock>
  </Tab>
  <Tab>
    You might receive a `200 OK` or `201 Created` with initial results or confirmation directly.
  </Tab>
</Tabs>

**Key Goal of This First Call:** Get a successful response (e.g., `202 Accepted`, `200 OK`), NOT `401 Unauthorized` or `403 Forbidden`. This confirms your API key and authentication format are correct.

<Callout type="failure" title="If You Encounter Errors:">
  - **`401 Unauthorized`**: Issue with API key or `Authorization` header. Double-check them.
  - **`400 Bad Request`**: Issue with JSON payload or other parameters. Validate JSON and compare with endpoint specs in Section 4.
  - Refer to **Section 3.5 (Comprehensive Error Handling)** for more troubleshooting.
</Callout>

<Callout type="success" icon="party-horn" title="Congratulations!">
  Successfully making this first authenticated call is a significant milestone. You are now ready to explore the full capabilities of the Weir AI API detailed in subsequent sections and the API Endpoint Reference (Section 4).
</Callout>
